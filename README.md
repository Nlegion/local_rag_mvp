
# 🤖 Локальная RAG-система для внутренних процессов

Проект представляет собой локальную RAG-систему (Retrieval-Augmented Generation), предназначенную для ответов на вопросы о внутренних процессах компании на основе эталонных документов в формате YAML.

## ✨ Возможности

- 🔍 Семантический поиск по базе знаний компании
- 🤖 Автоматическое создание задач в Jira для определенных процессов
- 💬 Интуитивный веб-интерфейс на Streamlit
- 🏠 Полная локальность работы (без внешних API)
- 📊 Детальное логирование всех операций
- 🔧 Гибкая настройка процессов через YAML-файлы

## 🛠 Технологии

- **Python 3.12+** - основной язык разработки
- **LangChain** - фреймворк для RAG-систем
- **ChromaDB** - векторная база данных
- **Sentence Transformers** - модели для эмбеддингов
- **Llama.cpp** - локальные LLM модели
- **Streamlit** - веб-интерфейс
- **PyYAML** - работа с YAML-файлами

## ⚙️ Установка и настройка

### Предварительные требования

- Python 3.12 или новее
- 8+ GB оперативной памяти
- 5+ GB свободного места на диске

### 1. Клонирование репозитория

```bash
git clone <URL репозитория>
cd local_rag_mvp
```

### 2. Создание виртуального окружения

```bash
python -m venv venv
source venv/bin/activate  # Linux/Mac
# или
venv\Scripts\activate     # Windows
```

### 3. Установка зависимостей

```bash
pip install -r requirements.txt
```

### 4. Загрузка модели

Поместите модель в папку `models/`. Рекомендуемая модель: [
saiga_mistral_7b_gguf](https://huggingface.co/IlyaGusev/saiga_mistral_7b_gguf/blob/main/model-q4_K.gguf)

### 5. Настройка YAML-файлов

Добавьте свои YAML-файлы с описанием процессов в папку `data/`. Пример структуры файла:

```yaml
# data/procurement.yaml
metadata:
  process_name: "Закупка товаров и услуг"
  process_owner: "Отдел закупок"
  version: "1.2"
triggers: ["закупка", "купить", "procurement", "50", "100"]
categories:
  - category_id: "T1"
    description: "Закупка на сумму до 50 000 руб."
    steps:
      - step_id: "T1-1"
        description: "Создать заявку в Jira"
        user_instruction: "Создайте заявку в Jira по ссылке: https://jira.example.com"
```

### 6. Инициализация системы

```bash
# Первоначальная инициализация векторной базы данных
python -c "from core.rag_service import RAGService; rag = RAGService(); rag.initialize()"
```

## 🔧 Настройка процессов

### Добавление нового процесса

1. Создайте новый YAML-файл в папке `data/`
2. Опишите метаданные, триггеры и шаги процесса
3. Переиндексируйте базу знаний:

```bash
python -c "from core.rag_service import RAGService; rag = RAGService(); rag.initialize()"
```

### Настройка автоматических действий

Для автоматического создания задач в Jira добавьте секцию `system_action` в YAML-файл:

```yaml
steps:
  - step_id: "GP1-1"
    description: "Автоматическое создание заявки в Jira"
    system_action:
      type: "create_jira_issue"
      project_key: "PROC"
      issue_type: "Task"
      summary_template: "Групповая закупка: {user_query}"
      description_template: |
        Иницирована групповая закупка на основании запроса пользователя.
        Детали запроса: {user_query}
    user_instruction: "Система автоматически создала заявку в Jira"
```

## 📊 Логирование

Система использует единую систему логирования с ротацией файлов. Логи сохраняются в папке `logs/` в формате:

```
logs/
├── rag_system_20250101.log
├── rag_system_20250102.log
└── ...
```

Каждый log-файл ограничен размером 10 МБ, сохраняются последние 5 версий каждого файла.

## 🐛 Поиск и устранение неисправностей

### Проблема: Не загружаются YAML-файлы

**Решение:** Проверьте синтаксис YAML-файлов с помощью онлайн-валидатора.

### Проблема: Медленная работа системы

**Решение:** 
1. Убедитесь, что используется достаточно мощное железо
2. Проверьте, что модель загружена корректно
3. Уменьшите значение `k` в функции поиска

### Проблема: Не создаются задачи в Jira

**Решение:** Проверьте, что в YAML-файле правильно указана секция `system_action`.
